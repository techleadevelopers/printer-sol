O motor está alinhado e NÃO está comprando tokens mortos (saldo intacto em 1 SOL, 0 operações). Isso é ótimo.

MAS ele está rejeitando 100% dos tokens com a mensagem:
"Pump.fun API unavailable or incomplete; fewer than two WebSocket trades in the entry window"

Isso significa que a API está bloqueada/falhando e o WS não está entregando trades suficientes. Precisamos ajustar 3 coisas:

═══════════════════════════════════════════════════════════════
AÇÃO 1 — CONSERTAR A API (fallback de market cap)
═══════════════════════════════════════════════════════════════
Se a API pública da Pump.fun está falhando (403/429), precisamos de um User-Agent
ou headers corretos na requisição HTTP. Muitas APIs bloqueiam requests que não
parecem vir de um navegador.

AÇÃO:
1. Na função de polling/API em monitor.go (ou onde estiver o fetch), adicione:
   req.Header.Set("User-Agent", "Mozilla/5.0 (Windows NT 10.0; Win64; x64)")
   req.Header.Set("Accept", "application/json")
2. Se a API continuar falhando, use o fallback de conta RPC (bonding curve PDA)
   em vez da API HTTP.

═══════════════════════════════════════════════════════════════
AÇÃO 2 — BAIXAR OS LIMITES DE ENTRADA (para o bot comprar)
═══════════════════════════════════════════════════════════════
Atualmente: MIN_TXNS=5, MIN_VOLUME=1.5, ENTRY_DELAY=8s.
Em 8 segundos, a maioria dos tokens bons tem apenas 1 ou 2 trades (o dev e 1 comprador).

MUDANÇAS NO .env (e no config.go, se precisar):
- ENTRY_DELAY_SECONDS: de 8 para 5
- MIN_TXNS_BEFORE_BUY: de 5 para 2
- MIN_VOLUME_SOL_BEFORE_BUY: de 1.5 para 0.5

Isso não vai comprar token morto (0 txns / 0 vol), mas vai pegar o token que está
começando a bombar (1-2 txns, 0.5 SOL).

═══════════════════════════════════════════════════════════════
AÇÃO 3 — WEBSOCKET TRADES (garantir que o WS está lendo)
═══════════════════════════════════════════════════════════════
A mensagem diz "fewer than two WebSocket trades". Isso significa que o WS não
está recebendo eventos de trade.

AÇÃO:
1. Cole o log de conexão do WebSocket. O WS está realmente inscrito em
   `subscribeTokenTrade` para cada novo mint?
2. Se o WS estiver caindo constantemente, adicione reconexão automática.
3. Se o WS não entregar trade events para tokens novos (pump.fun limita),
   confie apenas na API pública como fallback (Ação 1).
