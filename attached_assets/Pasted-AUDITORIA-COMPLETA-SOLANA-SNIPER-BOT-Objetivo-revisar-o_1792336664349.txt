FASE 2 — BUGS CONHECIDOS A CAÇAR (cada um: localizar, corrigir, testar)
═══════════════════════════════════════════════════════════════════

2.1 RACE CONDITION em Engine.reserved
    Problema: e.reserved map é lido em reserve() e escrito em release()
    de goroutines diferentes (main loop + confirm goroutines).
    Ação: verificar se reserve/release usam e.mu.Lock() em todas as paths.
    Se algum release() do defer rodar sem lock, adicionar.

2.2 CONFIRM GOROUTINE SOBREVIVE AO SHUTDOWN
    Problema: e.confirm usa context.Background(). Em SIGTERM, goroutine
    fica pendurada tentando RPC.
    Ação: passar root context cancelável do main para confirm. Ou aceitar
    como graceful degradation (explicar no README).

2.3 RECONCILE NÃO REABRE POSITIONS
    Problema: Reconcile() marca state=confirmed mas NÃO chama OpenPosition
    se a posição sumiu. Live fica com bag na carteira mas DB vazio.
    Ação: em Reconcile(), quando status=confirmed/finalized E side=buy,
    chamar Execution() e OpenPosition(cost). Idem para sell → ClosePosition.

2.4 SEEN MAP SEM TTL em internal/tokenmonitor/monitor.go
    Problema: m.seen sync.Map cresce infinito. Em massa (1000+ mints/hora)
    estoura RAM.
    Ação: substituir por sync.Map + sweeper goroutine que apaga entradas
    com mais de 30min. Ou usar LRU (hashicorp/golang-lru).

2.5 TRACKED MAP SÓ APAGA EM EXIT SUCESSO
    Problema: m.tracked.Delete(mint) só roda em markTrade quando reason != ""
    e entry.Close* retorna nil. Se exit falha (RPC offline), mint fica
    tracked para sempre consumindo subscription.
    Ação: deletar tracked após N tentativas falhas OU usar TTL por mint.

2.6 MAXWAITSECONDS NÃO APLICADO
    Problema: env tem MAX_CONFIRMATION_WAIT_SECONDS=12 mas config.go pode
    ter default 45. Verificar se env override funciona.
    Ação: grep -n "MaxConfirmationWaitSeconds\|MaxWaitSeconds" e confirmar
    que o valor do env chega em Limits.

2.7 DAILY LOSS USA Truncate(24h) — alinhamento de epoch
    Problema: time.Now().UTC().Truncate(24*time.Hour) trunca em UTC midnight,
    não "últimas 24h". Funciona acidentalmente mas quebra se mudar fuso.
    Ação: manter comportamento (UTC midnight) mas comentar explicitamente.
    OU trocar para now.Add(-24*time.Hour).

2.8 CONFIG VALIDATION GAP
    Problema: config.go valida STOP_LOSS_PCT > 0 só em live. Em simulation,
    STOP_LOSS_PCT=0 passa. Paper trading sem stop testa errado.
    Ação: exigir STOP_LOSS_PCT > 0 em AMBOS os modos.

2.9 SELL SEM POSIÇÃO ABERTA
    Problema: CloseLivePosition checa db.PositionCost, mas se posição foi
    fechada por timeout e reaberta manualmente, pode vender 2x.
    Ação: verificar antes de Execute que side=sell e status='open'.

2.10 CORS DUPLICADO (função morta)
    Problema: api.go tem cors() lowercase (wildcard *) e corsPolicy() uppercase
    (origin explícito). cors() nunca é chamado mas está no arquivo.
    Ação: deletar cors() para evitar ativação acidental.

2.11 RUGCHECK SCALE
    Problema: code compara report.Score > 20. Se API retorna 0-1, condição
    nunca dispara.
    Ação: logar report.Score em cada Screen() e validar contra mint conhecido
    ruim. Se for 0-1, trocar threshold para 0.20 (ou normalizar).

2.12 ORDER DE VALIDAÇÃO EM Execute()
    Problema: reconciliation check roda DEPOIS de HasPurchaseForMint.
    Se trade anterior ficou unknown, HasPurchaseForMint retorna true e
    bloqueia sem nem chegar na mensagem "reconciliation required".
    Ação: mover ReconciliationRequired() para ANTES de HasPurchaseForMint.
